# v0.7.0 Development Plan — Private Internal OMO Runtime

**Status:** PLANNED — starts only after v0.6.0 is CLOSED
**Predecessor:** v0.6.0
**Product boundary:** personal and company-internal use only
**Upstream policy:** actual OMO source may run in a separately pinned private runtime; Shipping Core remains independent

## 1. Release outcome

Shipping Harness can delegate bounded execution to an actual private OMO runtime while retaining exclusive authority over scope, approval, budgets, evidence acceptance, blockers, human stop, SHIPPABLE, and CLOSED.

```text
Locked Shipping Goals/Tasks
  -> signed/hashed work order
  -> private OMO task execution
  -> normalized receipt
  -> Shipping re-verification
  -> Finisher decision
```

OMO task completion is a claim. Only Shipping acceptance checks can prove release completion.

## 2. User value

- stronger task and subagent execution without changing the simple v0.6 user experience;
- bounded model/agent selection;
- session and child-task recovery;
- controlled automatic continuation;
- truthful fallback when the runtime is unavailable;
- private internal reuse of proven OMO behavior rather than rebuilding a large runtime from scratch.

The user still says only:

> “Finish this project.”

The plugin may report that the internal OMO runtime is executing, but no OMO-specific operating knowledge is required.

## 3. Entry gate

v0.7 starts only when:

1. v0.6.0 is CLOSED and tagged;
2. the normal plugin/MCP workflow is stable;
3. the internal-only direction remains locked;
4. a private `shipping-harness-omo-runtime` repository or isolated workspace is available;
5. the exact OMO upstream pin is recorded;
6. upstream notices and modification records can be preserved;
7. public publishing paths are disabled;
8. Team Mode and DAG Mode remain disabled for the first pilot.

## 4. Included scope

### Private runtime repository

- pinned OMO upstream checkout or private fork;
- internal patch series;
- upstream and internal commit receipts;
- build artifact digest;
- compatibility manifest;
- preserved license and notices;
- `MODIFICATIONS.md`;
- selected upstream package tests;
- reproducible internal build;
- previous working runtime retained for rollback.

### Shipping bridge

- `shipping-omo/v1` work order schema;
- normalized task receipt schema;
- release/contract/Git/Goal/Task/acceptance binding;
- allowed and forbidden path binding;
- budget binding;
- runtime capability and health probe;
- start, status, steer, cancel, and receipt collection;
- same-session ownership proof;
- stale-signature suppression;
- continuation limit;
- Shipping pause/abort/close override;
- contract-approved fallback or durable BLOCKED.

### Runtime capabilities enabled

- task state and child runners;
- agent/category/model routing within a Shipping allowlist;
- routing provenance;
- maximum two parallel workers;
- maximum delegation depth one;
- maximum three automatic continuations;
- bounded task/fix/time/tool budgets;
- session suspend/resume;
- terminal task non-replay;
- exactly-once normalized completion delivery.

## 5. Explicit non-goals

- customer installation or distribution;
- public npm, source, binary, image, or container publication;
- OMO branding or marketplace;
- public SaaS;
- OMO memory/reflection;
- OMO telemetry unless explicitly disabled and reviewed;
- Team Mode;
- general DAG execution;
- unlimited concurrency, depth, continuation, time, turns, or cost;
- OMO authority over Shipping contract or release state;
- automatic OMO upstream update.

## 7. Authority boundary

### Shipping owns

- outcome, scope, and non-goals;
- contract and hash;
- acceptance criteria;
- budgets;
- human pause/abort;
- Goal/Task state accepted by Shipping;
- evidence freshness;
- issue classification;
- Finisher;
- release closure.

### OMO owns

- internal child-task/process lifecycle;
- runtime-local queue and task records;
- allowed agent/model route selection;
- bounded continuation and recovery;
- normalized task receipts.

### Denied actions

OMO must not:

- modify or approve `.shipping/contract.yaml`;
- increase any budget;
- create top-level work outside the supplied Goal/Task IDs;
- write forbidden paths;
- continue after PAUSED, ABORTED, BLOCKED, SHIPPABLE, or CLOSED when Shipping denies continuation;
- treat local task completion as release completion;
- accept a stale work order;
- revive another session's work.

## 8. Work order schema

Required fields:

```json
{
  "schema": "shipping-omo/v1",
  "work_order_id": "WO-...",
  "release_id": "project@0.7.0",
  "contract_hash": "sha256:...",
  "git_sha": "...",
  "shipping_session_id": "...",
  "goal_ids": ["GOAL-001"],
  "task_ids": ["TASK-001"],
  "requirement_ids": ["REQ-..."],
  "acceptance_ids": ["AC-..."],
  "allowed_paths": ["src/**", "test/**"],
  "forbidden_paths": [".shipping/**", ".git/**"],
  "budgets": {
    "parallel_workers": 2,
    "agent_depth": 1,
    "continuations": 3,
    "fix_cycles": 2,
    "wall_clock_seconds": 3600,
    "tool_calls": 200
  }
}
```

Unknown fields, unsupported schema versions, path escapes, stale Git SHA, and larger-than-policy budgets are rejected before runtime execution.

## 9. Receipt schema

```json
{
  "schema": "shipping-omo-receipt/v1",
  "work_order_id": "WO-...",
  "omo_task_id": "...",
  "shipping_task_id": "TASK-001",
  "status": "completed",
  "selected_agent": "builder",
  "selected_model": "provider/model",
  "routing_reason": "category-default",
  "started_at": "...",
  "finished_at": "...",
  "source_git_sha": "...",
  "result_git_sha": "...",
  "changed_paths": ["src/example.ts"],
  "evidence_refs": ["..."],
  "usage": {
    "turns": 4,
    "tool_calls": 12,
    "continuations": 1
  }
}
```

Shipping validates the receipt, repository state, scope, current SHA, and acceptance commands before changing Goal/Task or release state.

## 10. Default internal profile

```yaml
execution_engine: omo-internal
parallel_workers: 2
agent_depth: 1
continuation_limit: 3
fix_cycles: 2
team_mode: false
dag_mode: false
unlimited_values_allowed: false
human_stop_wins: true
shipping_finisher_only: true
public_publish: false
```

A value meaning unlimited in upstream configuration is invalid in the Shipping profile.

## 12. PR and implementation sequence

### PR-025 — Private runtime repository and pin contract

Build:

- private repository/workspace;
- exact upstream pin;
- internal patch structure;
- license/notice preservation;
- `MODIFICATIONS.md`;
- runtime manifest and build digest;
- public publish disablement;
- selected package build/test command.

Exit:

- the runtime can be reproduced from recorded pins and no public artifact is produced.

### PR-026 — Shipping/OMO bridge protocol

Build:

- work order and receipt schemas;
- schema version negotiation;
- path and budget validation;
- runtime capability and health probe;
- start/status/cancel transport;
- structured errors.

Tests:

- stale work order;
- wrong contract hash;
- path escape;
- budget expansion;
- unknown schema;
- unavailable runtime.

Exit:

- the bridge cannot mutate Shipping policy or receive an unbounded order.

### PR-027 — Task, routing, and evidence integration

Build:

- selected OMO task manager/runner integration;
- allowed agent/category/model policy;
- routing provenance;
- normalized changed-path and usage receipts;
- Shipping Goal/Task mapping;
- post-run acceptance verification.

Tests:

- OMO completed but acceptance fails;
- unavailable selected model;
- route falls back within allowlist;
- changed forbidden path;
- receipt references wrong Task ID.

Exit:

- OMO completion alone cannot make a Shipping Task DONE or release SHIPPABLE.

### PR-028 — Continuation, ownership, and recovery

Build:

- Shipping stop decision before continuation;
- same-session owner token;
- stale signature suppression;
- continuation counter;
- suspend/resume integration;
- terminal non-replay;
- exactly-once normalized completion delivery.

Tests:

- pause before continuation;
- abort during child execution;
- closed release receives late completion;
- wrong session revival;
- duplicate completion;
- runtime crash and restart;
- continuation limit reached.

Exit:

- no OMO execution continues against a denied Shipping state.

### PR-029 — Internal pilot, update, and rollback

Build:

- selected upstream package gate;
- bridge integration suite;
- disposable canary;
- one real internal project pilot;
- previous pin retention;
- update and rollback scripts;
- fallback to contract-approved Codex/Generic or BLOCKED.

Exit:

- one real release closes through OMO and the previous runtime can be restored without changing the active Shipping contract.

## 13. Test strategy

### Unit

- work-order/receipt schemas;

### Integration

- Shipping Task -> OMO task -> receipt -> Shipping verification -> Task DONE;
- unhealthy runtime fallback;
- runtime crash/recovery;
- pause/abort propagation;
- update/rollback with unchanged Shipping contract.

### Adversarial

- OMO edits contract;
- OMO increases budget in receipt;
- late receipt after CLOSED;
- cross-session task revival;
- stale SHA receipt;
- duplicate completion;
- upstream unlimited value;
- public publish script becomes enabled;
- missing license notice;
- malicious child claims SHIPPABLE.

## 14. Acceptance criteria

| ID | Criterion |
|---|---|
| AC-0701 | A separate private runtime is reproducible from recorded upstream pin, internal patch commit, build digest, and compatibility version. |
| AC-0702 | Upstream notices and an internal modification inventory are preserved. |
| AC-0703 | Work orders and receipts bind release, contract hash, Git SHA, session, Goal/Task, scope, acceptance, and budgets. |
| AC-0704 | OMO cannot modify or approve the Shipping contract, increase budgets, or transition SHIPPABLE/CLOSED. |
| AC-0705 | The default profile enforces workers <= 2, depth <= 1, continuations <= 3, Team/DAG disabled, and no unlimited values. |
| AC-0706 | Shipping pause/abort/close denies continuation, revival, and late work. |
| AC-0707 | Foreign-session, stale-SHA, wrong-task, or out-of-scope receipts are rejected. |
| AC-0708 | OMO task completion remains untrusted until current Shipping acceptance checks pass. |
| AC-0709 | Runtime/model unavailability results in approved fallback or durable BLOCKED, never fabricated success. |
| AC-0710 | Runtime crash/restart does not replay terminal work and completion delivery is deduplicated. |
| AC-0711 | An upstream update is promoted only after selected tests, bridge tests, canary, and compatibility checks pass. |
| AC-0712 | The previous runtime pin and artifact can be restored without reopening or amending the active Shipping contract. |
| AC-0713 | No public/customer package, source, binary, image, container, or endpoint is produced. |
| AC-0714 | v0.7.0 closes after one real internal OMO-backed release, all regressions pass, and zero blockers remain. |

## 16. Completion and next-version transition

v0.7 is complete only after a real internal project closes through the OMO runtime with no false completion, no stop-authority violation, and proven rollback.

v0.8 may start only when measured pilot evidence shows a real coordination bottleneck that a bounded Team/DAG graph is likely to solve. OMO feature availability is not sufficient justification.
