# v1.1.0 Development Plan — Nested Workspace Intelligence and Proposal Refinement

**Status:** PLANNED — minor release after v1.0.2  
**Predecessor:** v1.0.2 CLOSED  
**Primary field case:** Git repositories whose real product runtime lives below the repository root

## 1. Release outcome

Shipping Harness identifies the actual runnable workspace, derives acceptance commands with the correct working directory, infers the next version from mechanical evidence, and refines one proposal instead of creating replacements.

```text
Git repository
  -> bounded workspace candidates
  -> selected product workspace
  -> manifest-derived commands + cwd
  -> one versioned proposal
  -> refine revisions
  -> human approval
```

## 2. Included scope

### Bounded nested workspace discovery

Search tracked files only, with deterministic depth, count, byte, and path limits, for:

- `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`;
- `Makefile`, `Taskfile.yml`, `justfile`;
- `docker-compose.yml`, `compose.yml`;
- `RELEASE_MANIFEST.json` and release-status metadata;
- workspace README files.

Ignore generated, dependency, vendor, build, secret, symlink-escape, and `.shipping` paths.

### Workspace scoring

Score candidates from mechanical facts:

- runnable manifest and existing lockfile;
- source/test presence;
- aggregate verification target;
- release manifest/version evidence;
- documentation and operational scripts;
- tracked-file concentration;
- relation to the user goal.

Return a recommended workspace plus confidence and alternatives. Ask the user only when two materially different product candidates remain tied.

### Acceptance command extraction

- detect Make targets: `verify`, `package`, `smoke`, `integration`, `e2e`, `web-check`, `release-check`, `lint`, `typecheck`, `check`, `build`, `test`;
- prefer aggregate targets and avoid known duplicate subordinate targets;
- preserve command source, confidence, and workspace-relative `cwd`;
- append repository-root `git diff --check` only as a supplemental criterion;
- prohibit arbitrary host-supplied shell text.

### Version evidence

Read bounded mechanical version sources:

- release manifest;
- package/project manifest;
- Shipping CLOSED receipts;
- annotated Git tags;
- selected workspace name only as low-confidence evidence.

Classify the proposed change:

- verification, packaging, docs, or compatibility correction -> patch;
- backward-compatible user-visible behavior -> minor;
- approved compatibility break -> major.

Expose confidence and evidence; do not silently rewrite an explicitly user-selected version.

### `shipping_refine`

Add a ninth beginner tool that accepts only bounded structured refinements:

- proposal ID/hash;
- answers to canonical questions;
- selected workspace candidate ID;
- explicit user-authorized mode change;
- request to rescan repository evidence.

It creates `revision + 1` under the same proposal identity, links the previous hash, supersedes the previous revision, and reruns deterministic validation. It never accepts raw command, argv, environment, shell, credential, deploy, push, or arbitrary path fields.

## 3. Explicit non-goals

- executing discovered commands during planning;
- recursive monorepo orchestration across multiple products in one release;
- automatic commits, stashes, merges, pushes, or deployment;
- free-form model-authored acceptance commands;
- production certification from repository prose;
- changing Shipping authority or budgets.

## 4. Data model additions

```text
workspaceCandidate
  id, root, manifests, types, score, confidence, evidence

proposal
  id, revision, previousHash, activeRevision, workspace, versionEvidence

acceptance
  command, cwd, source, strength, aggregateOf
```

All new fields are hash-bound and size-limited.

## 7. Representative fixture

```text
repo/
├── README.md
├── docs/
└── evoharvest-runtime-v1.1.0/
    ├── Makefile          # verify, package, web-check
    ├── RELEASE_MANIFEST.json
    ├── pyproject.toml
    ├── tests/
    └── src/
```

Expected proposal:

```text
workspace: evoharvest-runtime-v1.1.0
version: 1.1.1 (patch recommendation)
acceptance:
  - cwd=evoharvest-runtime-v1.1.0 command=make verify
  - cwd=evoharvest-runtime-v1.1.0 command=make package
  - cwd=. command=git diff --check
active proposals: 1
mode: AUTO unless explicitly authorized otherwise
```

## 8. Installation gate

Install the tagged package to an isolated prefix, load it through OMP, verify nine tools, create/refine a nested-workspace proposal, and prove the locked contract contains the exact `cwd`-bound acceptance set before closure.
