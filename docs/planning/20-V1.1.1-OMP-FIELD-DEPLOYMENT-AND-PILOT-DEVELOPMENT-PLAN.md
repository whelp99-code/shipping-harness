# v1.1.1 Development Plan — OMP Field Deployment and Nested-Project Pilot

**Status:** PLANNED — field hardening patch after v1.1.0  
**Predecessor:** v1.1.0 CLOSED  
**Target environment:** Ubuntu `jm` user, OMP 15.10.12, local STDIO MCP, personal/company-internal use

## 1. Release outcome

Package, install, and operate the v1.1 feature set as OMP's main development harness, then prove it against an EvoHarvest-shaped real project without permitting a false approval or false completion.

## 2. Included scope

### Tagged package and user-local upgrade

- create a deterministic `v1.1.1` package from the closure candidate;
- verify package identity, version, SHA-256, and clean isolated install;
- upgrade `~/.local/lib/node_modules/shipping-harness` and command links;
- preserve rollback metadata and the previously working package;
- never publish to a public registry.

### OMP main-harness upgrade

- preserve and back up `~/.omp/agent` configuration;
- register the installed `shipping-harness-mcp` as global STDIO MCP;
- expose nine tools including `shipping_refine`;
- keep approval mode `always-ask`;
- automatically allow planning/status/verification only;
- require user confirmation for scope approval, refine operations that contain user decisions, execution, blocker fix, pause/resume/abort, and close;
- update `AGENTS.md` and the Shipping skill to require canonical proposal fields.

### Field pilot

Run a non-destructive planning pilot against an EvoHarvest-shaped or actual available repository:

1. detect the nested runtime workspace;
2. generate one AUTO proposal;
3. verify pending status is truthful;
4. refine the same proposal when a workspace answer or exception choice is required;
5. confirm the authority-bearing acceptance contains `make verify`, `make package`, and root `git diff --check` with correct `cwd` values;
6. do not approve or modify the target project unless its existing dirty baseline is explicitly preserved by the user;
7. record a bounded pilot receipt with no source code or secret content.

### Operational evidence

- installer receipt;
- OMP MCP-manager connection receipt;
- tool inventory and approval policy hash;
- target-project pilot summary;
- rollback command and backup path;
- no-publication declaration.

## 3. Explicit non-goals

- resolving the target application's existing dirty worktree automatically;
- executing production deployment;
- claiming sandbox, Temporal, GitHub App, or customer-production readiness without evidence;
- changing OMP source beyond installation/configuration integration;
- enabling Team/DAG;
- public package publication or customer distribution.

## 4. Implementation slices

### PR-050 — OMP nine-tool main harness

- full release verification and adversarial suite;

- doctor/status checks from a fresh shell;
