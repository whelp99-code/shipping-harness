# v1.2.0 Development Plan — Safe Baseline Steward

**Status:** PLANNED — implementation is forbidden until v1.1.2 is CLOSED
**Predecessor gate:** v1.1.2 CLOSED, annotated tag valid, clean worktree

## 1. Release outcome

A non-developer can safely understand and preserve an existing dirty baseline before approving a release. Shipping classifies changes and proposes a bounded baseline plan; OMP may create a commit only after explicit user confirmation. Shipping never exposes raw Git mutation through MCP.

## 2. Included scope

- classify dirty entries as PRODUCT, RELEASE_EVIDENCE, AGENT_RUNTIME, SHIPPING_RUNTIME, GENERATED, or UNKNOWN;
- use tracked/untracked status and bounded path evidence rather than directory name alone;
- exclude `.shipping` runtime from product dirty counts;
- treat untracked agent runtime as non-blocking while tracked or ambiguous runtime remains blocking/UNKNOWN;
- return one baseline plan with candidate paths, excluded paths, rationale, and commit-message suggestion;
- return one canonical next action per state;
- support post-commit `shipping_refine(rescan=true)` on the same proposal identity;
- verify file-set stability between review and user-approved host commit;
- keep destructive discard out of the normal UI and tool surface.

## 3. Non-goals

- Shipping-executed commit, stash, reset, clean, checkout, or delete;
- automatic trust of `.omo`, `.senpi`, `.serena`, or any tracked runtime file;
- adding a tenth MCP tool;
- modifying OMP core, model routing, Team/DAG, remote deployment, or publication.

## 4. Requirements

- **REQ-BASE-001:** every dirty path has a deterministic category and blocking decision.
- **REQ-BASE-002:** UNKNOWN never becomes silently non-blocking.
- **REQ-BASE-003:** baseline-plan paths are hash-bound before the host performs a user-approved commit.
- **REQ-BASE-004:** baseline preservation approval is separate from release-scope approval.
- **REQ-BASE-005:** the same proposal ID is rescanned after preservation.
- **REQ-BASE-006:** each proposal state exposes exactly one next action.

## 5. Implementation sequence

### PR-056 — Dirty change classifier

Parse porcelain status safely, account for rename pairs and tracked state, classify bounded path roles, and publish summary counts.

### PR-057 — Baseline plan and next-action model

Generate candidate/excluded path sets, suggested commit message, file-set hash, and a single next action without mutating Git.

### PR-058 — Preservation handshake and rescan

Add bounded refinement fields for an explicitly reviewed baseline receipt. Reject file-set drift and preserve proposal identity across the post-commit rescan.

### PR-059 — OMP UX and EvoHarvest pilot

Update the OMP skill/AGENTS rules and prove the flow on an EvoHarvest-shaped dirty repository without committing or discarding target files during automated tests.

## 7. Rollback and release gate

Rollback is `v1.1.2`. Closure requires classifier and handshake adversarial tests, non-destructive EvoHarvest fixture/pilot evidence, full regression, zero blockers/unknowns, CLOSED receipt, annotated `v1.2.0`, and clean source.
