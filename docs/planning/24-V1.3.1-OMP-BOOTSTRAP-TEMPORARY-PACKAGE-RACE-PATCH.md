# v1.3.1 Development Plan — OMP Bootstrap Temporary-Package Race Patch

**Status:** IMPLEMENTED — release verification and closure pending
**Predecessor:** v1.3.0 CLOSED, annotated tag `v1.3.0`, clean source
**Incident:** v1.3.0 user-local bootstrap preview passed, but apply failed before installation because its temporary package disappeared

## 1. Root cause

`bootstrapOmpMainHarness()` returned the asynchronous `installOmpMainHarness()` Promise from inside a `try/finally` without awaiting it. JavaScript executes the `finally` block before the returned Promise settles, so the temporary packaging directory could be deleted while installation was still reading the archive. Pack and install were tested separately, so the real bootstrap-apply lifecycle was not covered.

## 2. Release outcome

The bootstrap function waits for installation, doctor, receipt, and backup completion before deleting temporary package files. A real end-to-end bootstrap apply test reproduces the exact lifecycle, proves the temporary archive remains available, verifies the installed version and nine-tool OMP configuration, and proves rollback remains available. OMP 18.0.10 binaries must remain byte-identical during field deployment.

## 3. Included scope

- await the complete install operation inside `bootstrapOmpMainHarness()` before temporary cleanup;
- add a deterministic end-to-end bootstrap-apply regression using a disposable home, user prefix, fake OMP 18 host, and real local npm packaging;
- verify package install, backup manifest, doctor, receipt, nine tools, and explicit rollback;
- retain existing automatic rollback and failed-install behavior;
- update version, compatibility, operator documentation, traceability, and release records to v1.3.1;
- after source closure and annotated tag, deploy v1.3.1 to the actual user-local OMP 18 environment, preserving OMP launcher/core hashes;
- run installed doctor, MCP protocol/tool inventory, receipt audit, and non-destructive EvoHarvest pilot.

## 4. Non-goals

- changing proposal, baseline, intelligence, coverage, or isolation semantics;
- changing OMP core, router, provider settings, or model routing;
- adding MCP tools or changing the nine-tool schema;
- public publication, push, deploy, Team/DAG, or network listeners;
- modifying the EvoHarvest target project during the field pilot.

## 5. Requirements

- **REQ-BOOTSTRAP-001:** temporary package cleanup begins only after installation settles.
- **REQ-BOOTSTRAP-002:** real bootstrap apply is covered as one operation, not only pack/install fragments.
- **REQ-BOOTSTRAP-003:** successful bootstrap produces a healthy doctor and truthful install receipt.
- **REQ-BOOTSTRAP-004:** rollback restores the previous package and managed OMP configuration.
- **REQ-BOOTSTRAP-005:** field deployment preserves OMP 18 launcher/core bytes and nine tools.
- **REQ-BOOTSTRAP-006:** failed deployment never fabricates completion or mutates the target project.

## 6. Implementation sequence

### PR-064 — Reproduce and patch cleanup ordering

Add a failing full-bootstrap lifecycle test, then change the Promise return to an awaited install so `finally` cleanup is ordered after completion.

### PR-065 — Bootstrap apply and rollback evidence

Verify current package install, backup manifest/package digest, doctor, receipt, OMP tool inventory, explicit rollback, and no temporary archive dependency after completion.

### PR-066 — Full release and field deployment

Run all regressions, security, license, docs, OMP main-harness and smoke gates; close/tag v1.3.1; deploy from the tag; verify actual OMP hashes, installed version, receipt, nine MCP tools, and EvoHarvest read-only pilot.
