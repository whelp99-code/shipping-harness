# v1.6.1 Development Plan — Autopilot Field Hardening

**Status:** REPLANNED — v1.6.0 is CLOSED/tagged/clean; a preserved blocked rehearsal proved the version-bound security inventory must be in scope before lock
**Predecessor gate:** v1.6.0 policy and state-machine acceptance complete
**Purpose:** prove the new autonomy boundary against diverse real-world repository shapes before wider internal use

## 1. Release outcome

The policy-authorized autopilot survives adversarial, interrupted, multi-project, and model-variant field trials without false close, unauthorized consequence, history rewrite, or target-project mutation outside an exact policy. All defects found in the accepted v1.6.0 scope are fixed as a patch; optional expansion is moved to NEXT.

## 2. Included scope

- run read-only and disposable-copy pilots for EvoHarvest, Second Brain, AI CRM/PM, nested monorepo, small Node, Python, CLI, and migration fixtures when locally available;
- compare no-model, weak-host, strong-host, and hostile-host outputs for authority equivalence;
- test dirty baseline, missing acceptance, missing rollback, core-value deferral, security/auth changes, destructive migration, external network, cost, license, production, and public release scenarios;
- test duplicate calls, process crashes, interrupted commits, stale Git SHA, stale train/policy hashes, partial receipts, and recovery;
- test long-running verification, fix-budget exhaustion, pause/abort races, and next-release advancement;
- enforce zero false `READY_FOR_APPROVAL`, false `AUTO`, false `SHIPPABLE`, false `CLOSED`, and automatic `RELEASED`;
- add bounded performance and storage-retention checks;
- refresh and verify the version-bound security inventory whenever authority-bearing autopilot code changes;
- improve deterministic Korean reporting only where field evidence shows ambiguity;
- preserve all v1.6.0 authority and default-deny boundaries;
- deploy the final tagged patch to the actual OMP 18.0.10 environment, preserving binary hashes.

## 3. Non-goals

- adding new autonomy categories or permissions;
- enabling production/public deployment;
- enabling Team/DAG;
- adding MCP tools;
- changing user policy without an explicit higher-version migration;
- hiding failed pilots or converting field findings into PASS through prose;
- fixing unrelated product ideas discovered during pilots.

## 4. Field matrix

Each lane records repository fingerprint, policy hash, train hash, action decisions, state transitions, receipts, mutations, and final authority state.

| Lane | Required proof |
|---|---|
| Clean small project | safe local train can complete to CLOSED in disposable copy |
| Dirty nested project | exact preservation plan, no runtime pollution, no false approval |
| Missing acceptance | STOP/REPLAN, never AUTO close |
| Database migration | ASK or STOP without rollback proof |
| Auth/security change | ASK or STOP under default policy |
| External/cost/public | ASK or STOP; RELEASED remains false |
| Host model variants | identical train/policy/authority hashes |
| Crash/restart | no duplicate commit, verify, close, or next-release activation |
| Pause/abort race | human authority wins immediately |
| Core-value deferral | `INSUFFICIENT_VERSION_VALUE` or REPLAN_REQUIRED |

## 5. Implementation sequence

### PR-081 — Field harness and immutable evidence bundle

Create bounded pilot orchestration, disposable worktree/copy handling, before/after fingerprints, and machine-readable evidence bundles.

### PR-082 — Adversarial model and authority matrix

Inject weak, strong, absent, and hostile host prose; prove identical authority and safe presentation.

### PR-083 — Crash, replay, and transition hardening

Exercise process termination at every mutation boundary, replay receipts, fix partial state, and guarantee idempotent recovery.

### PR-084 — Performance, retention, and operator report

Bound planning/decision latency, train and action-log size, retained receipt count, and produce a concise internal operator report.

### PR-085 — Actual OMP deployment and rollback proof

Install from annotated tag, preserve `omp`/`omp-core` hashes, verify nine MCP tools, doctor, receipt, backup, rollback preview, and non-destructive real-project status.

## 6. Requirements

- **REQ-FIELD-001:** every pilot records immutable before/after Git and filesystem fingerprints.
- **REQ-FIELD-002:** target projects are read-only or disposable copies unless their policy explicitly allows exact mutations.
- **REQ-FIELD-003:** host model variants cannot change train, policy decision, value gate, or close authority.
- **REQ-FIELD-004:** partial/replayed receipts cannot repeat a commit, verify, close, or release activation.
- **REQ-FIELD-005:** pause/abort wins at every transition boundary.
- **REQ-FIELD-006:** all consequence classes are exercised and default policy remains deny-by-default.
- **REQ-FIELD-007:** no pilot may claim PASS with missing evidence or skipped mandatory lane.
- **REQ-FIELD-008:** performance and retention remain bounded.
- **REQ-FIELD-009:** any discovered blocker is fixed and reverified; optional findings move to NEXT.
- **REQ-FIELD-010:** actual OMP deployment preserves OMP binaries and supports exact rollback.

## 10. Rollback

Source rollback is annotated tag `v1.6.0`. User installation rollback uses the v1.6.1 install receipt and stored package digest. Rollback pauses any active train, preserves all audit history, and never converts a rolled-back package into release authority.
