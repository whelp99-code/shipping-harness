# v1.8.1 Development Plan — Goal Direction Field Hardening

**Status:** IMPLEMENTING
**Predecessor gate:** v1.8.0 is CLOSED, annotated-tagged, and clean.
**Purpose:** prove that bounded Goal Discovery, Direction Critic, Decision Ledger, Goal Charter, Release Train, and policy Autopilot behave as one model-independent field flow without target mutation, false authority, unbounded interviewing, or external release effects.

## 1. Release outcome

A broad product outcome can be analyzed against repository evidence, refined through at most two bounded product-level interview rounds, converted into one evidence-bound direction and Goal Charter, then handed to the existing Release Train and Autopilot without changing the nine-tool MCP surface. The field suite must prove identical authority results under no-model, weak-model, strong-model, and hostile-model commentary; detect stale, replayed, tampered, concurrent, and interrupted flows; preserve real project fingerprints; and keep `CLOSED != RELEASED`.

## 2. User value

The user can give one result-oriented instruction and receive a safe development path without answering implementation questions. The user is interrupted only for material product consequences that Shipping cannot safely determine from evidence. Safe local work remains automatable, while production, public, customer, data-destructive, authentication, security, license, cost, credential, and external-write consequences remain human-owned.

## 3. Scope

### Included

- One integrated field matrix for specific, vague, conflicting, delegated-default, interrupted, replayed, and hostile-model goals.
- Deterministic comparison of canonical proposal state, direction hash, Goal Charter hash, Release Train hash, policy decision, next action, and release authority.
- Append-only Decision Ledger verification across answer, recommendation, acceptance, supersession, and replan events.
- Exact Goal Charter binding to proposal revision/hash, Git SHA, contract hash, baseline SHA, Release Train hash, approver, and acceptance time.
- Stale proposal, stale direction, stale charter, source drift, scope drift, acceptance weakening, and core-value deferral attacks.
- Pause, abort, crash-recovery, duplicate request, concurrent refinement, and replay protection.
- Real-project read-only pilots for EvoHarvest, Second Brain, and AI CRM when available.
- Performance and retention limits for interview compilation, charter compilation, ledger reads, and integrated status projection.
- OMP 18.0.10 compatibility, exact nine MCP tools, installation receipt, doctor, rollback preview, and unchanged OMP binaries.
- Updated requirements, traceability, security inventory, compatibility, handover, MCP, beginner, OMP, and operations documentation.

### Excluded

- A tenth MCP tool, raw shell, arbitrary command fields, background workers, public listeners, or automatic deployment.
- Paperthin runtime or full skill-catalog dependency.
- OMO Team/DAG default activation.
- Ouroboros-style infinite mutation or reopening of a CLOSED version.
- Model-authored approval, verification, close, deployment, or `RELEASED` authority.
- Automatic production, public, customer, external-write, cost, license, destructive-data, authentication, security, privacy, legal, or credential consequences.
- Git push, merge, customer contact, purchase, public publish, or production deploy.

## 7. Stop and replan conditions

Stop instead of weakening acceptance when any of the following occurs:

- A material goal remains unresolved after two bounded rounds.
- A model changes canonical state, direction, charter, train, policy, or closure authority.
- A real project fingerprint changes.
- Rollback evidence is unavailable.
- Any false READY/AUTO/SHIPPABLE/CLOSED/RELEASED counter is non-zero.
- MCP tools differ from nine or OMP binaries change.
- A production, public, customer, external, cost, data, authentication, security, license, or credential consequence appears.

## 8. Completion meaning

v1.8.1 is complete only when Shipping Harness itself reports `CLOSED`, all required acceptance checks pass on the closure Git SHA, annotated tag `v1.8.1` points to that commit, the worktree is clean, the tagged package is installed and doctor-verified in OMP 18.0.10, rollback preview succeeds, and no evidence claims `RELEASED`.
