# Shipping Harness v1.13.0 — Dirty-Tree Friction

## 1. 문제

실제 사용(jmai-os-pack, 2026-09-17)에서 PATCH 릴리스 하나에 사용자 결정이 여덟 번 필요했다. 원인을 픽스처로 재현해 세 가지 결함을 확인했다.

### 1.1 더러운 트리에서 제안을 만들면 나중에 버린다

| 커밋 시점 | 하네스 반응 | 결과 |
|---|---|---|
| 승인 **전** 선행 커밋 | `ERR_PROPOSAL_STALE: Repository HEAD changed after proposal creation` | 제안 폐기. 재스캔 후 사용자가 승인 브리프를 다시 검토 |
| lock **후** 선행 커밋 | 오류 없음, SHIPPABLE, 차단 0건 | 선행 커밋이 릴리스 diff에 흡수됨 |

하네스는 더러운 트리를 받아 제안을 만들어 놓고, 사용자가 정리하면 그 제안을 버린다. 정리를 미루면 증거가 오염된다. 정리 시점을 사용자가 맞춰야 하는 구조 자체가 문제다.

### 1.2 lock 이후 커밋이 릴리스에 조용히 흡수된다

제안이 만드는 `scope.paths.include`는 분석기가 찾은 소스 루트 전부다. 픽스처에서는 `README.md`, `package.json`, `scripts/**`, `src/**`, `test/**`로 사실상 리포 전체였다. lock 이후 목표와 무관한 파일을 커밋해도 범위 이탈로 잡히지 않고 통과하며, receipt는 승인 범위에 없던 작업이 섞인 트리를 증명한다.

### 1.3 목표가 지목한 경로가 범위에서 빠진다

```
목표: "Implement hello() in a new file src/index.mjs so the existing test suite passes"
제안된 scope.paths.include: ["README.md","README.rst","README.txt","package.json","test/**"]
```

베이스라인에 `src/` 디렉터리가 없으면 분석기가 찾지 못하고, 목표 문장에 경로가 적혀 있어도 읽지 않는다. 그대로 구현하면 첫 verify가 `Unapproved scope drift: src/index.mjs`로 차단된다. 신규 프로젝트와 새 영역을 만드는 계획 단계가 모두 해당한다.

## 2. 목표

셋을 모두 없앤다. 사용자는 커밋 시점을 결정하지 않고, 승인 후 커밋은 증거로 남으며, 목표가 지목한 경로는 범위에 들어간다.

## 3. 고정 원칙

- 하네스가 만드는 git 변경은 **로컬·되돌릴 수 있는 커밋 하나**뿐이다. push·tag·amend·rebase·`reset --hard`·브랜치 전환은 하지 않는다. 안전 경계(`docs/HANDOVER.md`)는 그대로다.
- 추적되지 않은 파일을 무조건 담지 않는다. `src/adapters/artifacts.mjs`의 `BLOCKED_BASENAMES`(자격증명류)를 재사용해 걸러내고, 하나라도 걸리면 **커밋 자체를 거부**하고 파일명을 보고한다. 조용히 빼고 진행하지 않는다.
- `.gitignore`가 무시하는 파일과 `.shipping/**`는 어떤 경우에도 스테이징하지 않는다.
- 범위를 넓히는 근거는 사용자가 승인한 목표 문장뿐이다. 넓힌 사실과 이유를 승인 브리프에 드러낸다.
- 1.2의 판정은 차단이 아니라 증거다. 커밋이 목표와 관련 있는지는 결정론적으로 판단할 수 없으므로, 기록해 사람이 보게 한다.
- MCP 툴은 9개를 유지한다. 입력은 optional 가산만. 표면 동결 해시 갱신과 사유 기록.

## 4. 구현 단계

### Phase A — 베이스라인 자동 커밋 (1.1)

1. `src/core/baseline-commit.mjs`(신규):
   - `collectBaselineChanges(root)` → `{ trackedModified, untracked, shippingSkipped }`. `git ls-files --others --exclude-standard`로 untracked를 구해 무시된 파일이 절대 들어오지 않게 한다. `.shipping/**`는 제외.
   - `screenUntracked(paths)` → `BLOCKED_BASENAMES` 위반, 개별 8 MiB 초과, 총 200개 초과를 검사. 위반 시 `ShippingError('ERR_BASELINE_UNSAFE_UNTRACKED', …, { path, reason })`.
   - `commitBaseline(root)` → `git add -u`, 통과한 untracked만 `git add -- <path>`, 고정 메시지로 커밋. 반환 `{ sha, files, untrackedIncluded, undo }`.
   - 커밋 메시지(고정, 작성자 귀속 줄 없음 — 사용자 자신의 작업이다):
     ```
     chore: commit working tree before the shipping-harness proposal

     Recorded by shipping-harness <version> so the release baseline is one commit.
     Undo: git reset --soft HEAD~1
     ```
   - 실패 시 `ERR_BASELINE_COMMIT_FAILED`에 git stderr를 담아 던지고, 인덱스를 `git reset -q`로 되돌려 스테이징 잔여물을 남기지 않는다.
2. `shipping_start` 입력에 optional `commitBaseline`(boolean, **기본 true**). false면 기존 동작.
3. `createScopeProposal` 진입 직후, 저장소 분석 **전에** 실행한다. 변경이 없으면 무동작. 커밋했으면 그 SHA가 제안의 `baselineSha`가 된다.
4. 원장에 `baseline.autocommitted` 이벤트(sha, 파일 수, untracked 수)를 남긴다. 상태 전이는 아니다.
5. 응답: `structuredContent.baselineCommit = { sha, filesCommitted, untrackedIncluded, undo }` 또는 `null`. 텍스트 맨 위에 한 줄로 알린다.
6. **이미 통과하는 인수 조건 경고.** 자동 커밋이 구현 작업을 베이스라인에 넣으면 그 릴리스는 아무것도 증명하지 못한 채 닫힐 수 있다. 자동 커밋이 발생했을 때만 v1.12.1의 preflight를 돌려, 필수 인수 조건이 전부 이미 통과하면 `BASELINE_ALREADY_PASSING` 진단과 승인 안내 문장을 붙인다. 차단하지 않는다. preflight 자체가 실패하면 진단 없이 계속한다.

### Phase B — 승인 후 커밋 기록 (1.2)

1. `closeRelease`가 receipt에 `postLockCommits`를 쓴다: `baselineSha`(= lock 시점)부터 `closedGitSha`까지의 커밋을 `{ sha, subject, paths }`로. 유계: 커밋 50개, 커밋당 경로 20개, subject 120자. 초과 시 `truncated: n`.
2. `releaseStatus`에 `commitsSinceLock`(정수)을 더해 `status` 텍스트·MCP·릴리스 보고서에 노출한다. LOCKED 이후 상태에서만 계산한다.
3. 차단하지 않는다. `release.schema.json`에 가산 optional.

### Phase C — 목표가 지목한 경로 (1.3)

1. `src/core/goal-paths.mjs`(신규, 순수): `extractGoalPaths(goalText)` → 경로처럼 보이는 토큰을 뽑는다. 규칙:
   - `/`를 포함하거나 알려진 소스 확장자로 끝나는 토큰만.
   - 절대 경로, `..` 포함, `~` 시작은 버린다.
   - 유계: 최대 8개, 토큰당 200자.
2. `scopePathsForGoal(goalText, scopePaths, root)` → 각 경로를 글로브로 바꾼다. 파일의 상위 디렉터리 + `/**`. 상위가 리포 루트면 글로브 대신 그 파일 경로 그대로. 이미 include에 덮이면 추가하지 않는다.
3. 거부 규칙: `scope.paths.exclude`(`.git/**`, `node_modules/**`, `dist/**` 등)에 걸리거나 `.shipping/`으로 시작하면 추가하지 않고 `GOAL_PATH_REFUSED` 진단을 남긴다. `assertContainedPath`로 리포 밖을 막는다(파일이 실제로 없어도 된다).
4. 추가한 것은 `GOAL_PATH_ADDED: <glob> (goal named "<token>")` 진단으로 승인 브리프에 드러낸다.
5. 적용 지점은 제안이 계약의 `scope.paths.include`를 만드는 곳 하나다. 계획 단계(v1.12.0)의 `scopeInclude`가 있는 경우에도 같은 목표 문장에 대해 동일하게 적용한다.

### Phase D — 테스트

- `test/unit/baseline-commit.test.mjs`: 깨끗한 트리 → 무동작; 추적 수정만 → 커밋되고 SHA 반환; 무시된 파일과 `.shipping/` 제외; 안전한 untracked 포함.
- `test/adversarial/baseline-commit-attacks.test.mjs`: untracked `.env`/`id_rsa`/`credentials.json` → `ERR_BASELINE_UNSAFE_UNTRACKED`로 **커밋이 일어나지 않고** `git status --porcelain`이 호출 전과 바이트 단위로 같고 `git diff --cached`가 비어 있음; 8 MiB 초과; 200개 초과; `.gitignore` 대상 미포함.
- `test/integration/baseline-autocommit-flow.test.mjs`: 더러운 트리 → `shipping_start` → 자동 커밋 → 승인까지 `ERR_PROPOSAL_STALE` 없이 도달하고 `baselineSha`가 자동 커밋 SHA와 같음; `commitBaseline: false`면 기존 동작; 자동 커밋으로 전 AC가 통과하면 `BASELINE_ALREADY_PASSING`.
- `test/unit/post-lock-commits.test.mjs`: lock 후 커밋 2개 → receipt `postLockCommits` 길이 2와 경로; 커밋 없으면 빈 배열; 상한 초과 시 `truncated`.
- `test/unit/goal-scope-paths.test.mjs`: `src/index.mjs` → `src/**` 추가; 루트 파일 → 그 파일만; 이미 덮인 경로는 미추가; 최대 8개.
- `test/adversarial/goal-scope-attacks.test.mjs`: 목표 문장의 `../../etc/passwd`, `/etc/passwd`, `.git/config`, `node_modules/x`, `.shipping/state.json` → 전부 미추가 + `GOAL_PATH_REFUSED`; 1.3 시나리오 재현(빈 `src/`에서 목표가 `src/index.mjs`를 지목 → 구현이 scope drift로 차단되지 않음).

### Phase E — 문서

`docs/MCP.md`(shipping_start 입력·출력·되돌리기, 진단 코드), `docs/BEGINNER-QUICKSTART-KO.md`(더러운 트리로 시작해도 된다는 한 단락), `docs/HANDOVER.md`(하네스가 로컬 커밋을 만드는 유일한 지점과 경계, `postLockCommits`의 의미), `packages/shipping-plugin/skill/SKILL.md`, `CHANGELOG`.

## 5. 완료조건

- 더러운 트리에서 `shipping_start` → 승인까지 재스캔 없이 도달한다.
- 자격증명류 untracked 파일이 있으면 커밋이 일어나지 않고 오류가 파일명을 지목하며 트리가 그대로다.
- `.gitignore` 대상과 `.shipping/`은 어떤 경우에도 커밋되지 않는다.
- lock 이후 커밋이 receipt에 남고 `status`가 개수를 보여준다.
- 베이스라인에 없는 디렉터리를 목표가 지목해도 구현이 차단되지 않으며, 넓힌 범위가 진단으로 드러난다.
- 목표 문장을 통한 경로 탈출이 불가능하다.
- `commitBaseline: false`로 기존 동작을 그대로 얻는다.
- `npm run release:verify` 통과, 표면 동결 해시 갱신 사유 기록.
