# Shipping Harness v1.13.9 — 게이트 이식성

## 1. 문제

v1.13.8 이 `test:omp-main` 과 `smoke:omp-main` 을 처음으로 게이트 스텝에 넣었다. 로컬은
23/23 초록인데 GitHub 러너에서 둘 다 빨강이 났다.

### 1.1 테스트 헬퍼가 npm 경로를 굳혀 두었다

v1.13.8 이 `packages/omp-main-harness` 의 production 기본값 네 곳을
`defaultNpmCommand()` 로 바꿨지만, **테스트 쪽 일곱 곳은 그대로 두었다.**
`test/omp-main-harness/helpers.mjs` 와 두 테스트가 여전히 `/usr/bin/npm` 을 직접
spawn 해서 러너에서 `spawnSync /usr/bin/npm ENOENT` 로 죽었다.

그리고 `defaultNpmCommand()` 의 PATH 대체 분기는 **한 번도 실행된 적이 없었다.** 이
머신에는 `/usr/bin/npm` 이 있어서 항상 앞쪽 분기만 탔다. 러너가 타는 유일한 분기를
검증 없이 내보낸 셈이다.

### 1.2 돌 수 없는 스모크가 죽었다

`smoke:omp-main` 은 실제 OMP 호스트를 구동한다. 러너에는 `omp` 실행 파일이 없어
`spawnSync omp ENOENT` 로 죽었다. 이건 결함이 아니라 환경이다.

그렇다고 조용히 `exit 0` 으로 만들면 안 된다. **돌지 않은 스텝이 PASS 로 읽히는 것은
v1.13.8 이 없애려던 바로 그 실패 양식이다.** `release:verify` 의 skip 집계는 테스트
러너의 `ℹ skipped N` 만 세므로, 스크립트는 skip 을 보고할 방법 자체가 없었다.

## 2. 목표

게이트 스텝이 기여자 머신과 러너에서 다르게 동작하지 않게 한다. 다르게 동작해야 한다면
그 사실이 보이게 한다.

## 3. 고정 원칙

- 돌지 않은 스텝은 빨강도 초록도 아니다. WARNING 이다.
- 러너가 타는 분기는 러너만 타서는 안 된다. 테스트가 타야 한다.
- 한 가지를 고칠 때 같은 가정을 가진 나머지를 함께 센다.

## 4. 구현 단계

### Phase A — npm 해석 일원화

- `test/omp-main-harness/helpers.mjs`, `install-rollback.test.mjs`,
  `bootstrap-cleanup-race.test.mjs` 의 `/usr/bin/npm` 일곱 곳을 `defaultNpmCommand()`
  로 바꾼다.
- `defaultNpmCommand(env, preferred)` 로 선호 경로를 인자화한다. 그래야 `/usr/bin/npm`
  이 있는 머신에서도 대체 분기를 실제로 실행해 볼 수 있다.

### Phase B — 스크립트 skip 보고

- `packages/omp-main-harness/field-smoke.mjs` 는 `omp` 를 찾지 못하면 크래시 대신
  `SKIPPED: <사유>` 한 줄과 `{skipped:true, reason}` 을 내고 0 으로 끝난다.
- `countSkipped` 를 `scripts/release-verify-steps.mjs` 로 옮겨 순수 함수로 만들고
  `^SKIPPED: .+$` 를 한 건으로 센다. `release-verify.mjs` 는 import 해서 쓴다.

### Phase C — 테스트

- `test/unit/gate-skip-reporting.test.mjs`: 두 표식 집계, 느슨한 매칭 거부, 그리고
  실제로 스모크를 없는 호스트로 돌려 종료 코드와 출력을 확인한다.
- `test/omp-main-harness/npm-command.test.mjs`: 선호 경로를 없는 경로로 넘겨 PATH 대체
  분기를 실행한다.

## 5. 완료조건

- AC-11392 스크립트 skip 이 집계되고 WARNING 으로 나온다.
- AC-11393 `npm run release:verify` 전체 통과.
- AC-11394 문서 감사와 공백 검사.

## 6. 실행 기록

### Phase A — npm 해석 일원화

테스트 세 파일의 `/usr/bin/npm` 일곱 곳을 `defaultNpmCommand()` 로 바꿨다.
`defaultNpmCommand(env, preferred)` 로 선호 경로를 인자화했고,
`test/omp-main-harness/npm-command.test.mjs` 가 없는 경로를 넘겨 PATH 대체 분기를 실제로
실행한다. **그 분기는 v1.13.8 을 내보낼 때까지 어디서도 실행된 적이 없었다.**

`bootstrap-cleanup-race.test.mjs` 의 import 를 자동 삽입하다 여러 줄 import 문 한가운데에
넣어 `SyntaxError` 를 냈다. 게이트가 즉시 잡았다.

### Phase B — 스크립트 skip 보고

`field-smoke.mjs` 가 `omp` 를 못 찾으면 `SKIPPED: <사유>` 와 `{skipped:true}` 를 내고 0
으로 끝난다. `countSkipped` 를 `scripts/release-verify-steps.mjs` 로 옮겨
`^SKIPPED: .+$` 를 세게 했다. 실행되는 파일 안에 있던 함수라 테스트할 수 없었고, 순수
모듈로 옮기면서 비로소 고정할 수 있었다.

느슨한 매칭을 명시적으로 거부한다. 들여쓴 줄, 사유 없는 표식, 줄 중간의 단어는 skip 이
아니다. 그러지 않으면 아무 출력이나 게이트를 조용하게 만들 수 있다.

### Phase C — 테스트

`test/unit/gate-skip-reporting.test.mjs` 는 집계 함수만 보는 데 그치지 않고 스모크를
없는 호스트로 실제 실행해 종료 코드와 출력 형태를 확인한다. v1.13.8 에서 얻은 교훈이다.
수정을 격리해서 검증하면 수정이 만든 경로를 보지 못한다.

### 게이트

`npm run release:verify` 23/23 로컬 통과, `test:team-dag` skip 1건 WARNING.
CLOSED 1.13.9, 수용기준 4/4, 블로커 0.

직접 호출하므로, 이번에 만든 `SKIPPED:` 관례를 적용하면 게이트에 넣을 수 있다. 이번
범위에 넣지 않았다. 다음 판단거리다.

`release prepare` 가 직전 릴리스의 scope 를 그대로 복사하는 문제는 v1.13.8 §6 에 적어
