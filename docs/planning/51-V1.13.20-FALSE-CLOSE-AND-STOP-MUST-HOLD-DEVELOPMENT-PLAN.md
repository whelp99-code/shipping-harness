# Shipping Harness v1.13.20 — 거짓 CLOSE 와 멈추지 않는 STOP

## 1. 문제

v1.13.19 감사(아키텍트 + 울트라브레인 + 코어 대조)는 제품 목표
「프롬프트만으로 임의 프로젝트를 구동 가능한 MVP 까지」가 오늘 트리에서
부분적으로만 성립한다고 결론냈다. 그 목표의 본체(수락 단위, 준비 스코프,
골·차터·계약 통일)는 다음 버전이다. 그 전에 **닫힘과 정지가 거짓이면**
뒤에 쌓는 모든 CLOSED 를 믿을 수 없다.

이 버전은 그 신뢰 네 구멍을 닫는다. 코더를 만들지 않는다. MCP 툴은 아홉
개로 둔다. 명령/셸 필드를 표면에 넣지 않는다.

### 1.1 CLOSE 가 검증한 트리가 아니다

`closeRelease` 는 evidence `treeFingerprint` 를 비교하지 않는다
(`src/core/gate.mjs`). `assertFreshEvidence` 는 verify 경로에서
fingerprint 를 보지만 close 는 SHA + 현재 in-scope dirty 만 본다.
`docs/HANDOVER.md` 도 이 생략을 명시한다.

재현(감사): 실패 구현을 커밋 → 미커밋 통과 변경으로 verify → HEAD 를
건드리지 않고 실패 바이트로 복원 → `status` 는 `evidenceFresh: false` →
`close` 는 `CLOSED`. receipt 는 실패 커밋을, 버려진 작업의 증거로 증명한다.

### 1.2 읽기전용 start 가 Git 을 바꾸고 레포 코드를 돌린다

`createScopeProposal` 는 의도 분류·제안 로드 전에 베이스라인 커밋을 하고,
커밋하면 수락 preflight 를 돌린다. preflight 는 isolation/manual-only
메타데이터를 적용하지 않고 명령을 실행한다
(`src/core/proposals.mjs`, `src/core/contract-defect.mjs`).

재현: 명시적 읽기전용 분석 요청이 `ANALYSIS_COMPLETE` 를 돌려도 HEAD 가
바뀌고, 레포 테스트가 마커를 썼다. `--no-verify` 는 `prepare-commit-msg`
를 막지 못했다. 자격증명 스크리닝은 정확한 basename 과 **추가**만 보아
`.env.local` 이 자동 커밋됐다. `test/mcp/intent-gate.test.mjs` 는
`commitBaseline: false` 로 기본값을 피해 이 경로를 검사하지 않는다.

### 1.3 사람 pause 가 실행을 멈추지 않는다

`shipping_execute` 호스트 work order 경로는 `beginAgentRun` 에 들어가지
않고 릴리스 상태/`humanStop` 을 보지 않는다. 오토파일럿은 빠진
`humanStop` 을 false 로 본다 (`src/mcp/handlers.mjs`,
`src/core/autopilot.mjs`). MCP 프로토콜은 pause 를 실행/검증 뒤에
직렬화하고, `process.mjs` 는 취소 입력이 없다.

재현: `PAUSED` 인데도 구현 지시가 나왔다. `humanStop: true` 인데
오토파일럿이 `AUTO`/`IMPLEMENTING`. 수락 프로세스가 도는 중 pause+cancel
을 넣어도 부작용이 일어난 뒤 verify 가 `SHIPPABLE` 이고, 그다음에야
pause 가 끝났다.

### 1.4 예산과 무결성 세탁

`beginAgentRun` 이 `BLOCKED` 를 반환해도 `runner.mjs` 는 명령을 먼저
띄운다. 호스트 work order 는 agent-run 예산을 소비하지 않는다.
`maxVerifyRuns: 1` 이면 첫 성공 verify 가 `BLOCKED` 가 된다.

pause/resume 은 trusted state 가 아니라 일반 state 를 읽고 새 integrity
digest 를 쓴다 (`src/core/state.mjs`). 재현: 소진된 카운터를 파일에서
0 으로 고치면 `TAMPERED` → pause/resume 후 `VERIFIED` 가 되어 두 번째
fix cycle 이 실행됐다.

## 2. 목표

네 재현이 기본 MCP 인자·기본 CLI 경로에서 실패했다가, 이 버전 코드에서
거절되거나 무동작이 된다. 정상 lock→verify→close 의 판정과 횟수는
변하지 않는다.

이 버전이 **하지 않는 것** (v1.14+ 로 미룬다):

- 소프트웨어 골에 lint/`git diff --check`/문서 면제를 금지하는 수락 단위
- 라이브니스(포트 listen) 술어와 `start` 검출
- 승인된 준비 스코프(수락 부트스트랩)
- discovery 답을 잠긴 골/수락으로 컴파일
- 플랜 해시 바인딩 트레일 연속, 무관 골 거절
- 엔진 소유 구현 커밋, 열 번째 툴, 어댑터 work-order 프로토콜

미룬 이유는 본체가 아니라 전제이기 때문이다. 거짓 CLOSE 위에 MVP 수락을
쌓지 않는다.

## 3. 고정 원칙

- MCP 툴 아홉 개. 입력은 optional 가산만. `command`/`shell`/`args`/`argv`/
  `env`/`environment` 금지. 표면 동결 해시가 바뀌면 6장에 사유를 적는다.
- 모델은 승인·종료 권한이 없다. pause/abort 가 모든 자동 연속보다 앞선다.
- Git 쓰기는 기존과 같이 `baseline-commit.mjs` 한 곳. push·tag·amend·
  `reset --hard` 없음. ANALYZE_ONLY / PLAN_ONLY 에서는 그 한 곳도 기본
  경로에서 돌지 않는다.
- `TAMPERED` 는 pause/resume/abort 로 치유되지 않는다. 복구는 신뢰할 수
  있는 역사 또는 검증된 백업뿐이다 (`docs/HANDOVER.md`).
- 기존 `UNVERIFIED_LEGACY` 프로젝트는 이 버전에서 차단하지 않는다.
- 적대 테스트는 타이밍 행운으로 통과하지 않는다. 취소는 프로세스 그룹
  신호로 증명하고, sleep 으로 기다리지 않는다.

## 4. 구현 단계

### Phase A — close 는 검증한 트리만 (1.1)

1. `closeRelease` 가 `assertFreshEvidence` 와 같은 fingerprint 비교를
   한다. HEAD 가 같아도 작업 트리가 증거 당시와 다르면
   `ERR_EVIDENCE_STALE`(또는 기존 코드와 같은 코드)로 거절한다.
2. `docs/HANDOVER.md` 의 「close 는 fingerprint 를 비교하지 않는다」
   문장을 삭제하고, close 가 비교한다는 문장으로 바꾼다.
3. 회귀: 실패 커밋 → dirty pass verify → 실패 바이트 복원 → close 거절.
   커밋된 통과 트리의 정상 close 는 통과.

### Phase B — 분석은 기본으로 읽기전용 (1.2)

1. 의도 게이트가 `ANALYZE_ONLY` 또는 `PLAN_ONLY`(또는
   `CONFIRMATION_REQUIRED` 전의 기본 분석)이면 `commitBaseline` 기본값을
   적용하지 않는다. `IMPLEMENT` / `AUTOPILOT` 으로 확인된 뒤에만 기본
   커밋이 남는다. 호출자가 `commitBaseline: true` 를 분석 모드에 명시하면
   거절하거나, 커밋하지 않고 진단을 남긴다(둘 중 하나를 구현에서 고르고
   테스트로 고정).
2. 수락 preflight 는 **lock 직전** 또는 IMPLEMENT 진입 후로 옮긴다.
   분석 경로에서 레포 소유 명령을 실행하지 않는다.
3. 베이스라인 커밋이 남는 경로에서도 hook 면제를 문서화한다.
   `prepare-commit-msg` 가 레포 코드를 실행하면 커밋을 거부하는 쪽이
   안전 경계와 맞다. 자격증명 스크리닝은 추가뿐 아니라 이미 추적 중인
   수정 경로의 basename 도 본다. 하나라도 걸리면 전체 커밋 거부
   (기존 `ERR_BASELINE_UNSAFE_UNTRACKED`).
4. `test/mcp/intent-gate.test.mjs` 가 **기본 인자**로 읽기전용 요청을
   넣고, HEAD·작업 트리·사이드이펙트 파일이 불변임을 주장한다.

### Phase C — pause 가 실행과 work order 를 이긴다 (1.3)

1. `shipping_execute` / `shipping_fix_blockers` 의 호스트 work order
   반환 전에 `humanStop` 과 상태(`PAUSED`/`ABORTED`/`CLOSED`)를 본다.
   정지면 `ERR_HUMAN_STOP`(또는 동등)이고 구현 지시 없음.
2. 오토파일럿 `evaluateAutopilotAction` 은 `humanStop === true` 또는
   `PAUSED` 이면 `STOP` / `allowed: false`. 기본값 false 로 누락을
   메우지 않는다. 상태를 모르면 STOP.
3. MCP in-flight 실행을 pause/abort 가 앞설 수 있게 한다. 최소:
   실행 중 pause 요청이 큐에서 무기한 대기하지 않고, 러너가 프로세스
   그룹에 신호를 보낼 입력을 갖는다. 완료 후 pause 는 결함이 아니다.
4. 회귀: PAUSED 픽스처에서 execute 가 work order 를 주지 않음.
   `humanStop` 픽스처에서 오토파일럿이 AUTO 가 아님.
   장시간 수락 명령 + pause 가 부작용 전에 프로세스를 죽임
   (이벤트 구독 후 트리거, sleep 금지).

### Phase D — 예산은 launch 전, 무결성은 세탁 금지 (1.4)

1. `executeAdapter` 는 `beginAgentRun` 이 던지거나 `BLOCKED` 를 반환하면
   **명령을 띄우지 않는다**. 실패 테스트: `maxAgentRuns: 0` 인 FIXING
   에서 마커 명령이 실행되지 않음.
2. 호스트 work order 경로는 실행이 아니므로 agent-run 예산을 소비하지
   않는 것은 맞다. 다만 정지면 1.3 에서 이미 거절한다. 주석으로 이
   구분을 고정한다.
3. `maxVerifyRuns: 1` 의 첫 **성공** verify 는 `SHIPPABLE` 이다.
   소진 판정은 실패한 반복 또는 중복 verify 에만 적용한다. 기존
   `maxRedundantVerifyRuns` 의미와 충돌하면 테스트를 먼저 고친다.
4. `pause` / `resume` / `abort` 는 `readTrustedState` 만 읽는다.
   `TAMPERED` 면 `ERR_STATE_TAMPERED` 이고 digest 를 새로 쓰지 않는다.
   회귀: 카운터만 0 으로 고친 뒤 pause/resume 이 두 번째 fix 를
   허용하지 않음.

### Phase E — 문서와 게이트

1. `docs/HANDOVER.md` 권한 순서에 위 네 보장을 한 단락으로 반영.
2. `BACKLOG.md` 에 v1.14 로 미룬 항목(수락 단위, 준비 스코프, 골 컴파일,
   플랜 바인딩 연속)을 적되, 이 버전 AC 로 끌어오지 않는다.
3. 적대 테스트는 `test/adversarial/` 또는 해당 스위트에 두고
   `release:verify` 가 돌리는 경로에 포함되게 한다. 새 `test/` 디렉터리
   나 `test:*` 스크립트를 만들면 스텝 또는 제외 사유가 필요하다.

## 5. 완료조건

- AC-113201: 1.1 재현 — fingerprint 불일치 close 거절, 정상 close 통과.
- AC-113202: 1.2 재현 — 기본 인자 읽기전용 start 가 Git·레포 명령을
  변경하지 않음. 추적 중 `.env.local` 수정은 베이스라인 커밋 거부.
- AC-113203: 1.3 재현 — PAUSED/`humanStop` 에서 work order·AUTO 없음.
  in-flight 수락이 pause 에 죽음.
- AC-113204: 1.4 재현 — 예산 소진 후 명령 미실행. TAMPERED 는
  pause/resume 으로 VERIFIED 가 되지 않음. `maxVerifyRuns: 1` 첫 성공
  verify 는 SHIPPABLE.
- AC-113205: `npm run release:verify` 전체 통과.

계약 명령은 픽스처를 도는 기존 `node --test` 패턴을 따른다. 문서만의
AC 로 네 구멍을 증명하지 않는다.

## 6. 실행 기록

미착수. 이 문서가 v1.13.20 의 범위 잠금이다. 구현은 계약 lock 이후.
