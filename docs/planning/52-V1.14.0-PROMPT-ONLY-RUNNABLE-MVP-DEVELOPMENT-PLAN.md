# Shipping Harness v1.14.0 — 프롬프트만으로 구동 가능한 MVP

## 1. 문제

v1.13.20 은 거짓 CLOSE 와 멈추지 않는 STOP 을 닫았다. 그 위에 올리기로
미룬 본체가 이 버전이다. 목표는 「프롬프트만으로 임의 프로젝트를 구동
가능한 MVP」다.

오늘 트리는 소프트웨어 골을 lint, `git diff --check`, 문서 감사만으로
SHIPPABLE 로 만든다. test/start 를 승인된 범위 밖에서 손으로
`contract.yaml` 에 적어야 하고, discovery 의 답은 차터에만 남는다.
트레인 연속은 버전 번호만 본다.

## 2. 목표

세 묶음만 닫는다.

- 소프트웨어 골은 앱을 띄우거나 이름 있는 사용자 결과를 단언하는 리포
  소유 검사가 없으면 SHIPPABLE 이 되지 않는다. 같은 묶음에 포트 listen
  라이브니스 술어와 `start` 검출이 있다.
- 호스트는 따로 승인된 준비 스코프 안에서 test/start 를 만들고 rescan
  한다. `contract.yaml` 을 손으로 고치지 않는다.
- discovery 답을 잠글 골과 수락으로 컴파일한다. 트레인 연속은 plan hash
  와 stage 에 묶이고, 무관한 골은 거절한다.

이 버전이 하지 않는 것:

- 엔진이 구현 커밋을 소유하는 것
- MCP 툴을 열 개로 늘리는 것
- 어댑터 work-order 프로토콜

## 3. 고정 원칙

- MCP 툴은 아홉 개. 이 버전은 툴 JSON 을 바꾸지 않는다.
- 준비 스코프의 승인자 이름이 `model`/`assistant`/`system` 이면 거절한다.
  discovery direction 은 승인·종료·릴리스 권한이 없다.
- 준비 쓰기는 승인된 상대 경로만. `.shipping/contract.yaml` 과 `.git` 은
  대상이 아니다.
- 블록커는 수락 ID 를 basis 로 인용한다.
- 기존 픽스처 골(소프트웨어 표지가 없고 `software-goal-unproven` 정책이
  없는 계약)의 close 는 바꾸지 않는다.

## 4. 구현

### 4.1 수락 증명 (BACKLOG-014)

`src/core/acceptance-proof.mjs` 가 명령을 lint / diff-check / docs /
start / liveness / other 로 나눈다. 소프트웨어 골이거나
`blockerPolicy` 에 `software-goal-unproven` 이 있으면, 필수 수락 중
증명 검사가 없을 때 `ISSUE-SOFTWARE-GOAL` 블록커를 낸다. 증명은
`npm start` 계열, `listen:<port>` 술어, 또는 약한 명령이 아닌 명령의
`User outcome:` 설명이다. `portListens` 는 TCP accept 만 참으로 본다.
`detectStartScript` 는 package `start` 를 검출하고, 분석 결과 `start`
에 싣는다. 검출된 start 를 필수 수락 명령으로 실행하지 않는다.

### 4.2 준비 스코프 (BACKLOG-015)

`prep approve` 가 `.shipping/prep-approval.json` 만 쓴다. `prep author`
는 승인된 경로에 test/start 파일과 `package.json` 스크립트만 쓴다.
`prep rescan` 은 `analyzeRepository` 로 다시 읽고 `contract.yaml` 을
쓰지 않는다. 범위 밖 경로는 `ERR_PREP_SCOPE`.

### 4.3 골 컴파일과 트레인 연속 (BACKLOG-016)

`compileDiscoveryLock` 이 ready direction 의 outcome 을 잠글 골로,
successCriteria 를 비약한 수락의 `User outcome:` 으로 옮긴다.
`compileDecisionContract` 가 direction 이 있을 때만 이 결과를 쓴다.
`assertTrainContinuation` 은 plan hash 와 stage 가 같을 때만 통과하고,
골 문장이 다르면 `ERR_TRAIN_UNRELATED_GOAL` 이다. 버전 일치는 신원이
아니다. plan 이 잠긴 계약으로 만든 트레인은 `continuity` 를 싣고,
`rotateAutopilotPolicy` 가 그 연속을 검사한다. continuity 가 없는 기존
트레인은 버전 검사만 유지한다.

## 5. 완료조건

- AC-114001: 약한 수락만 있는 소프트웨어 골은 SHIPPABLE 이 아니다.
  이름 있는 사용자 결과가 있으면 SHIPPABLE 이다. listen 술어와 start
  검출이 있다.
- AC-114002: 승인된 준비 스코프에서 test/start 를 만들고 rescan 하면
  검출되고, `contract.yaml` 바이트는 그대로다. 범위 밖은 거절이다.
- AC-114003: discovery 답이 잠글 골과 수락에 들어간다. plan hash 와
  stage 가 같으면 연속하고, 같은 버전이어도 다른 hash 나 무관 골은
  거절한다.
- AC-114004: `npm run verify:docs && git diff --check && npm run release:verify`.

## 6. 표면

CLI help 에 `prep approve|author|rescan` 을 넣는다. help 해시만
바뀐다. MCP 툴 JSON 과 `schemas/v1` 해시는 유지한다. 사유는 이 절이다.
