# Shipping Harness v1.14.1 — 검증 뒤 바뀐 트리로는 닫지 않는다

## 1. 문제

GitHub 이슈 #1. 검증이 SHIPPABLE 을 낸 뒤 커밋하지 않고 소스를 바꿔도
`close` 가 예전 증거로 CLOSED 를 냈다. 미커밋 변경은 HEAD 를 바꾸지
않으므로, Git SHA 와 계약 해시만 보는 대조로는 잡히지 않는다.

v1.14.0 트리에서 임시 fixture 로 재현한 결과:

- 검증 뒤 `package.json` 테스트 스크립트를 실패로 바꾸기: 기본 경로는
  `ERR_CLOSE_UNCOMMITTED` 로 거부되지만, 사유가 「증거가 오래됨」이
  아니다.
- 같은 변경에 `--allow-uncommitted`: CLOSED.
- 검증 때 이미 dirty 였던 scope 안 파일을 검증 뒤 다시 바꾸기: CLOSED.
- 검증 뒤 scope 안 새 파일, 추적 파일 삭제: `--allow-uncommitted` 로 CLOSED.
- 검증 도중 변경: verify 에서 이미 TRIAGE (재현 안 됨).

원인은 `closeRelease`(src/core/gate.mjs)다. v1.13.20 에서 증거 manifest
에 `treeFingerprint` 가 있는데도 close 는 그것을 대조하지 않고, scope 안
dirty 경로의 **이름**만 비교했다. 같은 경로의 바이트가 바뀌거나 새 경로가
생겨도 이름 비교는 통과한다.

## 2. 목표

close 는 증거가 실행된 트리와 지금 닫으려는 트리가 같을 때만 증거를
받아들인다.

이 버전이 하지 않는 것:

- close 에서 검증을 자동으로 다시 돌리는 것
- 엔진이 구현 커밋을 소유하는 것
- MCP 툴 JSON, `schemas/v1`, CLI help 변경

## 3. 고정 원칙

- `.shipping/` 런타임 파일은 여전히 트리 신원에서 빠진다. 하네스가 쓴
  증거·상태만 바뀐 경우는 소스 변경이 아니다.
- 검증 뒤에야 dirty 가 된 scope 밖 경로는 close 를 막지 않는다. HEAD 에도
  영수증에도 들어가지 않기 때문이다(v1.10.0,
  `test/adversarial/close-uncommitted-attacks`). 검증 때 이미 dirty 였던
  경로는 scope 와 무관하게 대조한다.
- 계약 해시, Git SHA, 사람 pause/abort, 필수 실패, 블록커, 미커밋 거부
  (`ERR_CLOSE_UNCOMMITTED`) 는 그대로다. 오래된 증거가 먼저 걸린다.

## 4. 구현

`src/core/git.mjs` 에서 `treeFingerprint` 의 digest 계산을
`dirtyTreeFingerprint(root, headSha, dirtyPaths)` 로 뽑아 export 한다.
값은 바뀌지 않는다.

`closeRelease` 는 현재 dirty 경로 중 (a) 증거가 기록한 dirty 경로이거나
(b) scope 안 경로인 것만 골라 fingerprint 를 다시 계산하고,
`assertFreshEvidence` 에 `treeFingerprint` 로 넘긴다. 다르면
`ERR_EVIDENCE_STALE`. v1.13.20 의 「복원된 scope 안 경로」 검사는 이
대조에 포함되므로 지운다. CLI `close` 와 MCP `shipping_close`(autopilot
close 포함)는 모두 `closeRelease` 를 거치므로 같은 경계를 쓴다.

`test/integration/plan-update.test.mjs` 의 plan 삭제 테스트는 검증 뒤에
plan 파일을 지워 close 의 plan 검사에 닿았다. 이제 그 순서는 오래된
증거로 먼저 거부되므로, 검증 전에 지우도록 옮긴다. 단언
(`ERR_PLAN_UNAVAILABLE_AT_CLOSE`) 은 그대로다.

## 5. 완료조건

- AC-114101: 검증 뒤 소스 변경(추적 파일 수정, scope 안 새 파일, 삭제,
  이미 dirty 였던 바이트 재수정)은 core `closeRelease`,
  CLI `close --allow-uncommitted`, MCP `shipping_close` 모두에서
  `ERR_EVIDENCE_STALE` 이고 상태는 SHIPPABLE 로 남는다. 검증한 dirty
  트리가 그대로면 런타임 파일과 검증 뒤 scope 밖 경로가 있어도 CLOSED 다.
  기존 미커밋 close 테스트는 그대로 통과한다.
- AC-114102: plan 이 묶인 릴리스는 stage 정의가 없으면 여전히
  `ERR_PLAN_UNAVAILABLE_AT_CLOSE` 로 닫히지 않는다.
- AC-114103: `npm run verify:docs && git diff --check && npm run release:verify`.

## 6. 표면

MCP 툴 JSON, `schemas/v1`, CLI help 해시는 바뀌지 않는다. 사용자에게
보이는 변화는 close 가 새 경우에 `ERR_EVIDENCE_STALE` 을 낸다는 것뿐이다.
